Features

What the service does when you submit a UID

01

Format check

The UID is matched against the configured digit range before anything is written, and rejected if it does not fit.

02

Slot allocation

A slot is reserved and the record is created as pending, so two submissions cannot collide.

03

Token signing

A per-record authorization token is issued with 24 bytes of randomness, and a separate activation token on completion.

04

Game handshake

The game reads the record through a single endpoint, guarded by a shared token, and expires on a fixed TTL.

05

Local store

Records live in one JSON file on this machine, rewritten on every change and reloaded on restart.

06

Rate limited

Per-IP request caps, body size limits and a strict UID pattern keep the service from being abused.
